# postcutoff

Your coding agent writes code from what it saw in training. If your project
pins a version released after the model's knowledge cutoff, the agent is
guessing at that version's API: it may write zod 3 code against zod 4, or
the 0.x fastmcp API against fastmcp 2.

`postcutoff` reads your lockfiles, looks up when each pinned version was
published on PyPI or npm, and tells you which ones the model cannot have seen,
how far ahead of the model they are, and the newest version it *could* know.
It can write that list into `AGENTS.md` / `CLAUDE.md` so the agent knows to
read the docs instead of trusting its memory.

- Zero dependencies (Python 3.9+ standard library).
- Reads `requirements*.txt` (`==` pins), `uv.lock`, `package-lock.json`
  (v2/v3) and, when there is no lockfile, `package.json` range floors.
- Only direct dependencies: the ones your agent actually writes code against.

## Install

```sh
pip install git+https://github.com/jatingargiitk/postcutoff
```

## Usage

Pass the model's training-data cutoff as `YYYY-MM` (read as the end of that
month) or `YYYY-MM-DD`. Model vendors publish these in their model docs.

The [`examples/demo`](examples/demo) project pins a mix of Python and npm
packages:

```console
$ cd examples/demo
$ postcutoff --cutoff 2025-01
knowledge cutoff: 2025-01-31   files: requirements.txt, package-lock.json
LEVEL        PACKAGE                PINNED  RELEASED    NEWEST BEFORE CUTOFF
NEW PACKAGE  openai-agents          0.1.0   2025-06-27  - (first published 2025-03-04)
MAJOR        npm:@anthropic-ai/sdk  0.57.0  2025-07-21  0.36.3 (2025-01-27)
MAJOR        npm:zod                4.0.5   2025-07-10  3.24.1 (2024-12-11)
MAJOR        fastmcp                2.3.4   2025-05-15  0.4.1 (2024-12-09)
MINOR        npm:typescript         5.8.3   2025-04-05  5.7.3 (2025-01-08)
MINOR        pydantic               2.11.3  2025-04-08  2.10.6 (2025-01-24)

7 deps: 1 new package, 3 major, 2 minor, 0 patch, 1 ok, 0 unknown
(1 ok row hidden; --all shows it)
skipped 1: requests (requirements.txt: not pinned with ==)
```

The levels, from least to most surprising for the model:

| level | meaning |
|---|---|
| `ok` | the pinned version was released on or before the cutoff |
| `patch` | only patch releases since the newest version the model may know |
| `minor` | a new minor version |
| `major` | a new major version (for `0.x`, a new minor counts as major) |
| `new-package` | the package itself was first published after the cutoff |
| `unknown` | not found on the registry, or the pinned version isn't published |

"Newest before cutoff" is the newest final (non-pre-release) version published
on or before the cutoff date.

### Tell the agent

`--write FILE` inserts the list into `FILE` between
`<!-- postcutoff:start -->` and `<!-- postcutoff:end -->` markers, and
replaces that block on later runs, leaving the rest of the file alone.
`--format md` prints the same block without writing anything.

```console
$ postcutoff --cutoff 2025-01 --write AGENTS.md > /dev/null
./AGENTS.md: updated
$ cat AGENTS.md
# Agent notes

Run tests with `pytest -q`.

<!-- postcutoff:start -->
## Dependencies newer than your training data

These pinned versions were released after 2025-01-31, so you have not seen them. Do not write code against them from memory: read the changelog or docs linked below first, and prefer what the installed package actually exposes. (Generated by postcutoff.)

- `openai-agents` 0.1.0 (the package did not exist yet, released 2025-06-27): https://pypi.org/project/openai-agents/0.1.0/
- `@anthropic-ai/sdk` (npm) 0.57.0 (new major version, released 2025-07-21); the newest version you may know is 0.36.3: https://www.npmjs.com/package/@anthropic-ai/sdk/v/0.57.0
- `zod` (npm) 4.0.5 (new major version, released 2025-07-10); the newest version you may know is 3.24.1: https://www.npmjs.com/package/zod/v/4.0.5
- `fastmcp` 2.3.4 (new major version, released 2025-05-15); the newest version you may know is 0.4.1: https://pypi.org/project/fastmcp/2.3.4/
- `typescript` (npm) 5.8.3 (new minor version, released 2025-04-05); the newest version you may know is 5.7.3: https://www.npmjs.com/package/typescript/v/5.8.3
- `pydantic` 2.11.3 (new minor version, released 2025-04-08); the newest version you may know is 2.10.6: https://pypi.org/project/pydantic/2.11.3/
<!-- postcutoff:end -->
```

### Gate CI

`--fail-on LEVEL` exits 1 when any dependency is at that level or worse
(`patch < minor < major < new-package`). For example, to fail when a newly
bumped dependency has a major version the model has never seen:

```console
$ postcutoff --cutoff 2025-06 --fail-on major
knowledge cutoff: 2025-06-30   files: requirements.txt, package-lock.json
LEVEL  PACKAGE                PINNED  RELEASED    NEWEST BEFORE CUTOFF
MAJOR  npm:@anthropic-ai/sdk  0.57.0  2025-07-21  0.55.1 (2025-06-30)
MAJOR  npm:zod                4.0.5   2025-07-10  3.25.67 (2025-06-16)

7 deps: 0 new package, 2 major, 0 minor, 0 patch, 5 ok, 0 unknown
(5 ok rows hidden; --all shows them)
skipped 1: requests (requirements.txt: not pinned with ==)
$ echo $?
1
```

`--format json` prints every finding with its release date, the newest
version before the cutoff, the first release of the package and the number of
final releases between the cutoff and your pin.

### Offline

Lookups are cached for a day in `~/.cache/postcutoff` (`--no-cache` turns
that off). `--registry-file dates.json` skips the network entirely and reads
release dates from a file shaped like
`{"pypi": {"name": {"1.2.3": "2025-04-08"}}, "npm": {...}}`; the test suite
uses this.

## Limits

- A release date before the cutoff doesn't guarantee the model learned that
  version well: releases from the last weeks before a cutoff are often thinly
  represented in training data. Treat `ok` near the cutoff with some care.
- The release date is the first upload of that version to PyPI, or its publish
  time on npm.
- `requirements.txt` lines that aren't `==` pins are listed as skipped.
  `poetry.lock`, `pnpm-lock.yaml`, `yarn.lock` and `package-lock.json` v1
  aren't read yet.

Exit codes: 0 ok, 1 `--fail-on` threshold hit, 2 usage or registry error.
